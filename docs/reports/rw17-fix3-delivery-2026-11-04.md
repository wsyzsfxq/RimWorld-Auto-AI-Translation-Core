## 本轮修改

| 反馈 | 处理情况 |
|---|---|
| 语言、供应商和界面翻译模式的下拉框样式不一致 | 共用“左侧标签＋右侧当前值框”的绘制入口，值框保留下拉箭头 |
| 工作台复核范围把标签塞进选项框，文字拥挤 | 标签移到框外，并给当前值更宽的显示空间 |
| 强制分析、DLL 分析、快捷入口和 Mod 名称开关没有统一 | 共用小框、绿勾／红叉、正文大小单行文字；按文字和图标计算宽度 |
| 按钮文字在框内换行或偏移 | 公共按钮使用局部单行样式，明确内边距和对齐；绘制后还原界面状态，不修改游戏共享样式 |
| 手动选择简体后重启变繁体，随后 XML 又过期 | 显式保存语言三字段、先保存同一设置对象再刷新缓存、识别带中文后缀的语言目录名，以及最小启动／手动保存日志；这些接线已独立静态审阅 |

纯界面样式调整不提高分析器版本。本轮沿用 `xml-3.02` 及 1.7 的 `dll-3.09-rw17`，不清空现有数据库或译文。

## 配置保存与部署范围

fix2 部署记录显示安装目录始终为 `Mods/AI_TranslationCore_Dev`，官方包 ID 和 Mod 目录名称没有改变。部署脚本仅读安装包运行文件清单，复制范围是 `1.7`、`Defs`、`Languages` 和 `LoadFolders.xml`，`About` 文件不覆盖。它没有写入 AppData 中的 `Config`、API 配置或游戏 Mod 名单。

这能确认部署脚本没有直接覆盖用户语言配置；游戏或 Mod 自身在随后启动时保存配置的行为，仍必须单独检查，不能据此排除持久化缺陷。调查没有输出 API 密钥。

本次既有数据库记录显示，四个 Mod 在 `03:37:16` 的 XML 分析目标为繁体、在 `03:40:20` 为简体，两批都是 `xml-3.02`。因此本轮“又过期”确有目标语言变化，不是又改了 XML 分析器版本。但 `03:34:21` 和 `03:39:41` 的旧语言回调日志没有记录选中值，不能据此认定用户选错，也不能证明更早一次简体保存已经成功。历史退回繁体的单一根因尚未证实，新日志用于让后续保存和加载过程可核对。

fix3 同样保留用户译文、数据库、备份、配置、存档和 Mod 名单，只更新本 Mod 的运行文件。安装包不含用户数据库、模型配置或缓存译文。
