## 上次修改的遗漏

上次只将 UI 模式的四个开关压到一行，动作按钮仍按 50% 宽度分配；DLL 模式则分别使用 190/210 的最小按钮宽度。UI 模式保留 200/240 的固定面板高度，DLL 模式固定 268，说明也使用不同的固定高度和间距。用户的新截图确认：此前产物没有把这两个分支作为同一块设置界面完整处理。

## 本次统一范围

- 两种模式的四个动作按钮共用 `GetCompatibilityActionRects`，使用同一个 Small 字体测量方法 `WorkflowUiStyle.ButtonWidth`，按文字加 24 的边距留宽，靠左排列。取消等分整行以及 190/210 的人为最小宽度。
- 按钮高度统一 32、同行间距 8、行距 6；放不下时整颗按钮移到下一行，不挤压两颗按钮来强行占满一行。
- “恢复 UI 自动翻译”也使用相同的紧凑宽度。清理缓存/黑名单保持红色 Stop，其余动作使用 Quiet；操作处理、启用条件及保存逻辑保留。
- 开关仍保持已确认的一行布局，两种模式统一开关行高及与下一行的距离。
- 说明和状态使用同一套 Tiny、MutedText、左上对齐及换行处理。先按实际文字高度和动作按钮行数计算面板高度，再分配空间，撤销 200/240/268 的固定面板高度，避免内容下面留出大块空白。
- DLL 模式特有的采集时限和证据说明继续显示，但沿用相同的间距和说明绘制方式。

静态核对了 SettingsTab 的两个分支、公共按钮样式、外层 Listing 的实际宽度来源以及暂停后的恢复分支。没有靠执行画面或自动测试判断显示效果。
