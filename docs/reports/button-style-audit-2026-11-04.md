# 按钮样式静态盘点

日期：2026-11-04。范围：本项目设置、工作台、编辑器、云端及弹窗的按钮／选择控件。依据为当前源码和本机 1.7 程序的已有只读 IL 记录；未编译、运行、测试、操作界面或截图验收。

阶段说明：上句记录本专项作者完成静态盘点时的状态。后续已纳入 [fix3 集成交付](rw17-fix3-delivery-2026-11-04.md)并生成 1.7 产物；实际部署／启动结果以交付记录为准，画面仍未自动验收。

## 结论

此前不只是颜色不一致，还存在共用按钮继承换行、控件宽度不足、动作误用下拉样式和旧窗口沿用另一套按钮等问题。当前用户确认的基准已抽成[控件标准](../standards/ui-controls.md)，对应接入已落源码。不能据此声称所有分辨率下画面已经验收。

## 用户截图的直接原因

1. 本机 1.7 的 `Widgets.Label → GUI.Label → GUIStyle.DrawTextIn → ImGuiGuiBackend.DrawText` 会传递文字对齐和换行；不是游戏简单丢掉了 MiddleCenter。
2. 原工作台把两个勾叉开关塞进七分之一列的一半，标记占 22 后四个汉字剩余宽度不足。选项行原高 27，按钮又扣去 2，文字继承 `WordWrap=true`；多行文字块在矮框中居中，会越过上边界被裁切，看起来像“上漂”。
3. 复核范围将名称及多个范围值挤在同一格，具有相同风险。fix3 曾外置标签并借用剩余行宽；用户随后明确要求仅占下方“AI 复核”按钮的一列。现已让两者共用同一列的矩形计算，组内单行展示，完整范围放悬浮提示，不再横跨其它操作列。
4. 语言、供应商、模式原来分别采用整行按钮、外置标签下拉和普通深色动作外观。现在共用左标签／右蓝灰框，框中只放当前值及箭头。

## 全盘分类及处理

| 类型／位置 | 原不一致 | 当前处理 |
|---|---|---|
| 共享文字绘制 | 默认换行；各调用者继承字体和边距 | 公共 `SingleLineLabel` 使用局部样式、零额外内边距／偏移、单行与明确对齐，恢复全局文字状态 |
| 强制分析、DLL 分析、快捷入口、名称翻译 | 有绿色大按钮、裸勾叉、小框；有宽度不足 | 四处共用 `ToggleButton`；按同样文字样式测宽；保留禁用、取消及保存条件 |
| 设置语言／供应商／界面翻译／复核范围 | 标签与值混在框内、不同底色 | `DrawSettingsDropdown` 转调公共 `LabeledDropdown`，原点击回调与模式语义不变 |
| 工作台分析状态 | 普通动作外观，却打开值选择菜单 | 改为外部名称＋当前筛选值；增加完整提示 |
| 编辑器分类、译文状态、手工分类 | 当前值与名称混写，手工生效时又变另一种边框 | 接公共下拉；人工层正在生效的底部标识保留 |
| 云端目标语种、版本 | 普通深色动作按钮，没有统一下拉外观 | 接公共下拉；版本框只显示版本号，来源／合并／日志保留在提示及选项中 |
| 旧 UI 管理来源、字典适用范围 | 金色普通按钮承担筛选 | 接公共下拉，完整值放提示 |
| 旧 UI 管理、字典、云优先级、名录同步 | 四个旧窗口直接使用金色 `Widgets.ButtonText` | 全部改为公共动作按钮；保存／应用、重置、删除／停止按原用途区分 |
| 编辑器 AI 翻译 | 实际是直接执行动作，却用 Dropdown 蓝框 | 改为普通动作；保留无模型置灰与翻译入口 |
| 上传预览 AI／人工／汉化组标记 | 互斥单选，原来三个都用 Dropdown 且没选中外观 | 使用现有选中／未选中样式，标记约束及禁止人工的条件不变 |
| 外层禁用 | 外层 `GUI.enabled=false` 时共享按钮仍可能画成亮色 | `Button` 和 `ToggleButton` 合并外层禁用条件，外观与点击条件一致 |
| 表单复选框／清单 | 与紧凑开关用途不同 | 原有清单和确认复选框保留，没有擅自改变多选或单选逻辑 |

在本次源文件枚举时，项目已经没有直接 `Widgets.ButtonText` 调用；图片按钮、列表行点击和折叠横条不是因此被改成普通动作按钮。共享外观并不代表这些不同用途全部改成同一种控件。

## 剩余边界

- 有效逻辑窗口较窄时，AI 卡片左列最低 500，右列再预留标签宽 105 和间距 28，会挤压模型、网址等右侧控件。当前设置页没有横向最小内容宽度保护。这是两列表单的响应式布局问题，不是已被单行按钮自动解决；本轮未擅自改成上下排。
- 极长型号名、Mod 名、用户自定义文本仍须按各控件宽度提供完整提示；单行裁切本身不是无限容纳长值的保证。工作台范围及本轮迁移的动态选择值已加提示，未展开成全部文本的自动缩放／省略算法。
- 其它原生表单复选框、云端多选筛选及上传互斥选项没有全部改为四个紧凑开关的外观。它们不是同一种交互；后续统一应按已确认的控件类别迁移。
- 实际字形、基线和不同 UI 缩放下观感仍需新包人工查看；本次没有运行验证。

## 文件与静态复查

核心入口：`UI/WorkflowUiStyle.cs`（Button、SingleLineLabel、ToggleButton、LabeledDropdown）。相关调用位于 `SettingsTab.cs`、`WorkflowMainTab.cs`、`WorkflowEditorTab.cs`、`Cloud/AutoTranslatorMod.CloudRenderers.cs`、`LegacyInterception/Window_UITranslationManager.cs`，以及 `Window_ReferenceDictionary`、`Window_CloudTranslationOrder`、`Window_ModCatalogSync`、`Window_UploadPreview`。

静态复查了下拉回调仍指向原设置／筛选操作，手工分类生效指示和上传来源校验未删除，禁用条件仍留在调用处；没有改模型调用、语言持久化、模式数据或用户文件。规则入口 `AGENTS.md`、`CLAUDE.md`、`GEMINI.md` 均已索引同一设计目录，本次在该目录登记标准，未向工程规则复制私人设定。

## 后续修正：复核范围与复核按钮同列

用户要求“复核范围”仅位于“AI 复核”正上方并左右对齐。`WorkflowMainTab` 的选项与动作现在共用七列的矩形计算，复核组固定第 3 列，不再依据上次试跑按钮右侧的剩余宽度延伸。只选一类时显示该类，多选两类显示“已选2类”，三类显示“全部”；完整范围仍在提示与原菜单中，筛选规则不变。空间不足时外部标签缩为“范围”，仍不借用其它列。

上次试跑入口保留在前两列余下空间，金额移入完整提示；若连短标题“详情”都放不下，选项区才增加一行，详情与下方试跑按钮同列，复核组仍在最靠近复核按钮的一行。强制分析／DLL 分析继续保留原开关行为。
