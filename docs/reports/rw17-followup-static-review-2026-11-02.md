## 已有译文的提前应用

游戏完成第一轮语言注入后，在主线程捕获本轮语言对象、目标语种、Mod 加载顺序及用户译文优先级；后台沿用现有 XML 读取与排序逻辑准备本地缓存，不初始化 SQLite，不调用 AI。

游戏完成最终语言注入后、集中执行启动静态构造之前，只应用已经准备好的同轮缓存。准备未完成、语言或目标变化、收到取消、文件变更或已有注入正在执行时，保留既有分帧加载；最终钩子不等待后台任务，不另开主菜单等待步骤。

提前应用复用现有 Keyed、Def 增量注入与原值记录，不改第三方文件。静态初始化之外的私有缓存、图片文字、尚未支持的 DLL 字段与复杂流向，不因这个时机调整自动获得覆盖。

提前应用 Def 后仍由正常分帧流程执行既有规范化，以处理自动生成的配方、尸体、肉类等派生文字。游戏数据清理时旧快照、应用状态、恢复基线和文件标记失效，后续启动加载可以按新一轮排队；旧任务不能发布为新一轮的结果。取消与文件通知使缓存失效，不把正常启动时的取消状态复位误判为用户取消。

## 仍然保留的边界

- 以上是代码与本机游戏程序集的静态结论，不是 SQLite 加载、Harmony 补丁或界面效果已经通过运行验收。
- 当前 1.7 资源目录尚不是完整安装包；未生成主 DLL，也未准备可发布的最终依赖组合。
- 后台准备未赶上最终语言回调时，当次继续普通加载，已经形成的不可刷新私有缓存仍可能保留原文；外部程序直接覆盖 XML 不会触发项目内的文件变更通知。
- 现有 DLL 注入仍有字段传递、分支汇合及包装类型等覆盖限制。本次没有引入新的通用文本替换架构。
- UI 采集及大型 DLL 性能工作、未匹配译文展示和未确认的群反馈继续按原待办范围处理。
- `tools` 中另外存在博德之门 3 的未提交脚本与中间产物。本次保留其文件，后续提交需与本项目变更分开整理。
