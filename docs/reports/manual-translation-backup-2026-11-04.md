# 手动译文备份与默认 UI 模式

状态：源码已修改，仅做静态审阅；未编译、测试或执行真实备份、恢复。

## 确认范围与入口

2026-11-04 用户确认手动备份包含 **XML、DLL 和 UI 拦截译文**。数据库文件、大模型配置和 API 密钥不进入备份。

设置的“维护与恢复”现在区分两行：

| 类型 | 按钮 | 内容与保存位置 |
|---|---|---|
| 译文自动备份 | 还原替换前译文 | 保留原行为：清除或替换某个 Mod 的文件前，保存该 Mod 的相关 XML 文件；仍在 `Backups/<packageId>/`，每个 Mod 最近三份。各 Mod 时间可能不同，只覆盖归档内文件。 |
| 手动备份译文 | 备份当前译文、恢复手动备份… | 同一次保存全部目标语言的 XML、DLL 清单、旧 UI 译文；单独放在 `ManualBackups/`。手动快照不自动删除。恢复列表注明“手动备份”或“恢复前保存”。 |

手动快照具体保存：

- `Languages/**/*.xml`。
- `HardcodedUiPatchPrototype.json`：DLL 译文及其定位清单。
- `UI_Hardcoded_Cache.json`：旧 UI 拦截译文。
- XML 的 `Languages/<language>/ATC_Provenance/*.json` 来源记录，以及快照内最小的条目来源元数据。它们随译文保存，避免恢复后把 AI 译文误算成人工，或把旧来源套给不同文本；不包含模型配置或密钥。

不保存旧 UI 黑名单、来源归属缓存、待处理队列、Mod 名称缓存、日志、数据库或 Mod 本体。快照的文件清单同时记录缺失类别；某类原来没有文件，恢复后应恢复为空。

## 生成与恢复流程

1. 取得全局任务互斥，暂停旧 UI 采集，取消其在途请求并等待退出，落盘当前 UI 译文。
2. 备份在后台压缩，完整写好后才发布为 ZIP。归档不递归包含备份目录。
3. 恢复时先完整读取快照信息、检查文件清单与归档内容并解压到临时目录；尚不改当前译文。
4. 将当前三类译文另存到 `ManualBackups/BeforeRestore/`。这类快照在选择列表中明确显示“恢复前保存”。
5. 恢复三类文件集合：覆盖快照中的文件，移除快照之后新增的译文文件，保留非译文文件。写入失败或取消时，使用恢复前快照退回原文件。回退也失败时保留回退 ZIP，并明确报告未完整恢复及其位置。
6. 按全部已有目标语言重新同步工作台状态。已经被用户快照取代的待写入、待删除任务会放弃，不能重放并复活快照以外的译文。
7. 按恢复后的文件刷新 XML、DLL 与旧 UI 内存。没有 DLL 清单的快照走明确的清补丁入口，普通运行中“清单意外丢失”的保护不变。不会为了恢复开启 DLL 模式或改用户开关。
8. 解除旧 UI 暂停，释放任务互斥。

已进入文件替换时，取消会先回退文件；文件替换已全部提交后，会完成状态同步与显示刷新，避免只恢复文件而留下旧的显示状态。文件成功、状态同步或显示刷新失败时，会明确提示“文件已恢复，但……”，不会把这些情况写成全部成功。

## 来源与数据库状态

数据库文件本身不备份、不替换。恢复操作重读恢复后的译文，更新工作台使用的译文状态，保留分类、当前语言与模型配置。

快照保存可用的原条目 ID、语种、文件/key、译文哈希、原文哈希、来源、原来源位置和实际 AI 供应商名称。只有文件/key、译文和当前原文均匹配，才恢复对应来源。不同文本不能继承当前数据库里的高优先级来源，也不因“文件和数据库不同”就假定是人工修改。无法核实的来源为未知；旧 AI/人工详情也会清理，不用另一条记录的模型或来源冒充。

XML 精确来源记录同时还原，配合现有云端上传的文件/key/文本检查。原文变化、占位符不合法等情况仍显示需要确认，并保留文件；不是放宽译文有效性判断。普通刷新同步的优先级及写回逻辑不变，仅显式手动恢复以所选快照文件为准。

## 默认模式

用户随后确认默认使用 UI 拦截模式。`UseLegacyUIInterception` 字段初值与配置缺失时的默认值改为 `true`；已有用户保存的 DLL 模式仍保留。没有修改实际用户配置，也没有额外改动拦截启用、自动翻译新文字等开关的原默认值。

## 独立静态复审补充

2026-11-04 限范围复审修正了两处具体缺漏：

- 恢复后的文件可能与恢复前文件恰好同长度、同修改时间。恢复专用同步现在先实际读取文件内容并核对哈希，不再仅凭时间和长度沿用旧索引；普通刷新仍使用原有缓存快路径。
- 恢复时新建数据库译文记录，也会写入快照中已核实的实际 AI 供应商名称。此前只有更新已有记录会写入，新增记录会丢失这项来源信息，影响之后的来源统计。

复审只静态阅读调用链、SQL 和改动后的代码；未执行编译、测试、实际备份或恢复。未再扩展备份范围或改变普通同步规则。
