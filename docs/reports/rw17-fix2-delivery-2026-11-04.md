## XML 已翻译却仍显示“泰南语”

ASF 和 ASGS 截图里的漏译来自 XML Keyed。既有日志、数据库和译文文件显示，中文已经生成；这两个 Mod 把首次查到的文字存进自己的静态字符串，之后仍显示旧缓存。它与 DLL 分析失败、DLL 硬编码译文注入失败是不同问题。

本轮已接入官方 Keyed 目录，以及显示和测量时按原键重新取当前译文的修改。分析前复制官方目录，按真实来源对应 Mod；补候选时使用全部可归属键，目标语言是否已有有效译文仍由现有检查判断，不把目录出现等同于再次调用模型。官方明确的 Keyed 自然语言条目属于需要翻译，旧 AI 否决在这一窄范围内不生效，人工分类仍最高。

XML 分析版本更新为 `xml-3.02`，需要重新分析时保留稳定条目 ID 和有效译文。显示桥接保留旧字符串的来源，支持完整缓存文字和普通数字／命名参数模板，无法消歧时保留原值。姓名使用缓存译文后再测宽与截断，避免先按英文建框、最后才画中文。上述链路已独立静态审阅，不能仅凭源码或构建声称截图中的所有文字已经在游戏内消失。

官方目录能提供已声明的翻译键和原文，不等于能覆盖从未调用本地化接口的全部 DLL 硬编码。显示时无法确定对应键的文字也不能猜测替换，更不能重写 Mod 的只读字段或重新执行初始化来掩盖问题。

## 两种备份和上传范围

- 自动备份：清除或替换某个 Mod 的 XML 译文前生成；不同 Mod 的备份时间可能不同，只还原各备份内的文件。
- 手动备份：同一份快照保存 XML、DLL 清单、旧 UI 译文；恢复前保存当前状态，恢复空类别时清掉快照之后新增的对应译文，文件恢复失败时回退。来源记录用于恢复 AI／人工标记，不是数据库备份。
- 批量上传：继续使用当前云端的 XML 协议。手动备份支持本地 DLL／UI JSON，不代表云端接口已支持上传这两类数据。

## 仍需分清的事项

1. 旧截图的全部“已过期”：既有数据库记录显示从繁中切到简中，分析器和 Mod 文件指纹当时没变。当前源码新增的 XML 规则升级会另行触发重新分析，二者不是同一原因。稳定条目 ID 和有效译文继续保留。
2. Neat Storage 的繁中云端 ZIP 原始内容含韩文。这是已核对的源包内容问题，本轮没有修改云端原始包，也不能断言究竟由上传者还是服务端造成。
3. ASGS 旧定点 DLL 清单的 9 条定位仍没有通过原链的显示参数检查。其中多条 `Original`、`All`、`None`、`x2` 对应官方 XML Keyed 声明，已接入新的 Keyed 显示处理；因此不能据此说新包这 9 条都不会显示，也不能说旧 DLL 注入链已全面支持。两条导入／导出错误、复杂模板及无法消歧的文字仍需分别看实际使用路径。
4. 思考模式有厂商和型号限制：有些模型必须思考，只能降档；未知网关保留默认；OpenRouter 依赖能力信息；Player2 沿用客户端设置；DeepL 没有此功能。没有发送真实请求确认服务端效果。
5. 游戏内字形、输入框边界、缓存刷新、备份恢复及上传仍需用户在交付包中实际查看；静态审阅和文件哈希不能替代这些验收。
